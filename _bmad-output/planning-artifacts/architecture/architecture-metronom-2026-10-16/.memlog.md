- (decision) Paradigm: functional core / imperative shell. Pure TS domain (ramp + validation) with no Angular/DOM/audio imports; shell = audio engine, session service, UI components, Electron main. Prevents ramp logic leaking into components or scheduler
- (decision) AudioContext clock is the single time source; lookahead scheduler (setTimeout tick ~25ms, schedule ~100ms ahead) owns beat timing; no setInterval per beat, no UI timers. Prevents drift and two clocks
- (decision) Ramp computed by pure function over bar index (tempoForBar), scheduler asks it at each bar start. Prevents scheduler and display disagreeing on tempo/hold/countdown
- (decision) Display sync: scheduler pushes {beat, bar, tempo, barsToNext, hold, audioTime} into a queue; one rAF loop in session service publishes the entry whose audioTime has passed. Components never compute beat state
- (decision) SessionService owns all session state as Angular signals; only start()/stop() mutate; components read-only. Zoneless (Angular default)
- (decision) Electron shell thin: main process only creates BrowserWindow and loads built app from file; contextIsolation on, nodeIntegration off, sandbox on, no preload, no IPC. Prevents renderer reaching Node
- (decision) Click synthesized with OscillatorNode + gain envelope (accent = higher pitch); no audio asset files
- (decision) Single window-level keyboard handler on root component for Space/Enter/Escape; preventDefault on Space. Prevents double-toggle from focused button
- (decision) Packaging: electron-builder, Linux AppImage target only. Reason: native AppImage support, simplest single-file local app
- (decision) Testing: Vitest (Angular CLI default) for pure core + session; FR-5 examples as table tests. No e2e in v1
