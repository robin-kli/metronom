- (event) Create intent: new brief started, no prior drafts or source material found in repo
- (decision) Product: metronome trainer (speed trainer) — core feature is automatic tempo increase after N bars, by % or by fixed BPM step, user's choice
- (decision) UI must be very slim/minimal: BPM select + ramp settings; while running, current position within the bar must be very clearly visible
- (decision) Form factor: web app built with Angular, used as a local app on Linux
- (event) Stakes read: personal tool for own practice, simple scope — right-size brief accordingly (no market rigor)
- (decision) Ramp model simplified: user sets a target BPM; ramp runs between a start % and end % of it (e.g. 50%->80%); end % is the ceiling where increase stops. Increase is percent-only (BPM-step option dropped)
- (assumption) Step size = X percentage points of target BPM every N bars (both user-set); at ceiling tempo holds and keeps playing; BPM rounded to integer
- (decision) 4/4 only; no time signatures or subdivisions
- (decision) Screen is close by, but beat/bar visualisation should still use all available space
- (decision) No saving/presets in v1
- (decision) Differentiator: free, simple, unbloated — existing trainers are bloated/complicated/paid
- (decision) Desktop packaging: Electron on Linux
- (decision) Use case: instrument speed practice (any instrument)
